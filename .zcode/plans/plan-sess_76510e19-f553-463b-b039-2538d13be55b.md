范围已收窄,排除所有安全项(S1-S4)、显示项(Locale/颜色)、授权项(B2)、UI 文案。本次只修「会崩溃」或「特定条件下功能失效」的 bug。每项改动小、独立、零运行风险。

## 崩溃类

### 1. PetViewModel 12 处 `viewModelScope.launch` 无 try/catch → 进程崩溃
**`ui/pet/PetViewModel.kt`**(行 49/59/82/99/150/386/480/571/635/716/915/951)
- 这些 launch 体调 `petRepository.loadPet()/savePet()`(Gson + SharedPreferences)或 `pet.tick()`。JSON 损坏 / 磁盘满 / tick 数学边界一旦抛异常,主调度器未捕获异常直接杀进程。
- PetViewModel 没继承 `ReloginViewModel`(那个基类自带 CoroutineExceptionHandler)。
- **修法**:给每个 launch 加一个统一的安全包装扩展 `ViewModel.launchSafe(block)`,内部 `try { } catch (e: CancellationException) { throw e } catch (e: Exception) { Logger.e(...) }`。改 launch 调用为 `launchSafe`。已含 try/catch 的不动。
- 先逐个核查 12 处哪些已有 try/catch(避免重复包裹)。

### 2. ElectiveParser `substring(startIdx, endIdx)` 越界 → 崩溃
**`data/parser/ElectiveParser.kt:258-259`**
- `parseOptions` 只查 `endIdx < 0`,没查 `endIdx < startIdx`。当页面里结束标签出现在开始标签之前(反常 HTML)时,`html.substring(startIdx, endIdx)` 抛 `StringIndexOutOfBoundsException`,无 try/catch 包裹 → 经 ViewModel 传到主线程崩溃。
- **修法**:加 `if (endIdx < startIdx) return`(与 `HtmlParser.parseSearchOptions` 已有的保护一致)。

## 边缘运行逻辑 bug

### 3. 并发 relogin 清掉刚拿到的新会话 → 请求连环失败
**`data/api/ReloginHelper.kt:25-30`**
- 两个并发请求都报会话过期 → 都调 `relogin()`。A 锁内登录成功;B 拿锁后无条件 `clearCookies()` 再登录,把 A 的新会话 cookie 冲掉。
- **修法**:`relogin()` 锁内幂等化——进入锁前快照 `userRepository.getUser().token`;拿到锁后再读一次,若 token 已变化(说明别的 caller 刚登录成功)且变化发生在最近(如 10 秒内),直接复用新 token 返回成功,跳过 clearCookies + relogin。失败则回退原逻辑。纯增量,不破坏现有路径。

### 4. 成绩解析正则列错位 → 备注字段显示错误
**`data/parser/ScoreParser.kt:106-110`**
- 正则回退路径 `isDelayExam`/`comment` 用 `groupValues[13]`、`makeupComment` 用 `groupValues[14]`;但 Jsoup 路径用 `cells[12]`/`cells[13]`。两条不一致,走正则的成绩会把补考备注显示在普通备注栏。
- **修法**:正则分支 `isDelayExam`/`comment` 改 `groupValues[12]`,`makeupComment` 改 `groupValues[13]`(与 Jsoup 路径对齐)。

### 5. 课表周选择器重复挂监听 → 导航状态不一致
**`ui/syllabus/GridSyllabusActivity.kt:312-334`**
- 先在 chip 构造时 `setOnClickListener`(312-315,不 dismiss),又给 `getChildAt(0)` 挂一个基于 `indexOfChild` 的(322-326),最后 for 循环覆盖所有 chip(327-333,会 dismiss)。三套监听混在一起,点 chip 行为不可预测。
- **修法**:删掉 322-326 的 `getChildAt(0)?.setOnClickListener` 块和 312-315 的内联 setOnClickListener,只保留 for 循环那个统一版本(循环内已 `navigateToWeek(0)` + `dialog.dismiss()`)。

### 6. 番茄钟后台/旋转丢进度,宠物不得经验
**`ui/timer/PomodoroTimerActivity.kt` + `AndroidManifest.xml`**
- `onDestroy` 里 `timer?.cancel()`,按 Home 销毁 Activity 后计时停止,用户拿不到"专注完成"和宠物 +10 经验。Manifest 无 `configChanges`,旋转重建。
- **修法**:① Manifest 该 activity 加 `android:configChanges="orientation|screenSize|keyboardHidden"`(旋转不重建)。② `onPause` 持久化 `isRunning`+`isBreak`+`endAt` 时间戳到 prefs;`onResume`/`onCreate` 恢复并校正(若 `endAt` 已过且当时在专注中,补发 `onComplete()`);`onDestroy` 仅清运行态不丢已持久化数据。不引入 Service,靠 prefs + 时间戳解决。

### 7. 课程提醒 requestCode 跨年重复 → 闹钟互相覆盖
**`service/CourseReminderReceiver.kt:195`**
- `requestCode = DAY_OF_YEAR * 100 + index + 10`,`DAY_OF_YEAR` 每年重复。去年与今年同一天的 PendingIntent 用 `FLAG_UPDATE_CURRENT` 互相覆盖,导致提醒错乱/丢失。
- **修法**:`requestCode` 乘入年份,如 `Calendar.YEAR * 100000 + dayOfYear * 100 + index + 10`,保证全局唯一。
